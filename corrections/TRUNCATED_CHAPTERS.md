# Truncated Chapters — Identification Pass (Blok 1)

Read-only analysis. No code changes, no database writes. Input for Blok 2 (targeted
regeneration). Generated by inspecting `handbook_chapters.content` endings against
each chapter's underlying source document size.

## Method

1. Ran the SQL heuristic (`rtrim(content) !~ '[.!?"»)\]]$'`) — flagged **107 of 382**
   chapters as not ending in sentence-terminal punctuation.
2. Classified all 107 by reading the last 120 characters of each. Most were
   unambiguous (mid-word or mid-sentence cutoff vs. a signature block / dated
   closing / contact info). **7 required reading the last ~500 characters** to
   resolve — see "Uncertain cases resolved" below.
3. Cross-checked the 60 chapters with the largest underlying source documents
   (`document_chunks` size) against their stored chapter length, looking for
   truncation that coincidentally lands on a period (e.g. an abbreviation) and so
   was invisible to the regex. Of 22 candidates with a large size gap, **1 genuine
   miss** was found; the other 21 were confirmed complete (mostly meeting-minutes
   and quality-procedure documents whose source is naturally repetitive/templated,
   so a small chapter-to-source ratio doesn't imply truncation there).
